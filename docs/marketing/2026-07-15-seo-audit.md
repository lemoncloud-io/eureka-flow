# SEO Audit — flow.eureka.codes (2026-07-15)

기술/온페이지 SEO 감사 리포트. 근거는 라이브 사이트 curl 응답(2026-07-15 KST)과 레포 `apps/web/index.html` 기준. JS 렌더링 후 DOM은 curl로 검증 불가하므로 해당 항목은 `[needs-verification]`으로 표시.

## Executive Summary

전반 상태: **기초는 잘 갖춰짐** — 정적 HTML에 title/description/JSON-LD(WebApplication)/Twitter Card/GSC·Naver verification/noscript 콘텐츠가 모두 있고, robots.txt + sitemap.xml + HTTPS(301) + CloudFront 캐싱도 정상. SPA치고 드물게 준비가 좋은 편.

최우선 이슈 3가지:

1. **sitemap의 10개 flow URL 전부가 동일한 정적 HTML을 서빙** — per-flow title/description/schema가 초기 HTML에 없어, 색인 대상으로 등록한 페이지들이 사실상 중복 문서로 보일 위험 (High)
2. **홈페이지(`/`)가 sitemap에 없음** — sitemap에 `/flows/*`만 있고 정작 루트 URL이 빠짐 (Medium)
3. **Open Graph 태그 부재** — Twitter Card만 있고 `og:*`가 없어 카카오톡/Slack/Facebook/LinkedIn 공유 시 미리보기가 깨짐 (Medium)

Quick wins: OG 태그 추가, canonical 추가, sitemap에 홈페이지 추가 — 셋 다 `index.html`/sitemap 생성부 한 곳 수정으로 끝남.

## Technical SEO Findings

### T1. SPA 딥링크가 전부 200 + 동일 HTML → per-flow 콘텐츠 없음

- **Issue**: `/flows/1005327-verbalized-sampling` 등 sitemap의 모든 URL이 같은 `index.html`(제목 "Eureka Flow — Visual AI Workflow Builder", 동일 description)을 반환. 존재하지 않는 flow id도 200을 반환해 soft-404 발생.
- **Impact**: High — 색인시키려는 public flow 페이지 10개가 검색엔진에 사실상 동일 문서. JS 렌더 후 client-side에서 title을 바꾸는지 여부는 `[needs-verification]` (Rich Results Test 또는 브라우저로 확인 필요). 바꾸더라도 초기 HTML 기반 크롤·소셜 크롤러에는 미노출.
- **Evidence**: `curl https://flow.eureka.codes/editor` → HTTP 200 (동일 HTML); sitemap의 flow URL과 루트 HTML 비교.
- **Fix**: public flow 페이지에 per-URL 메타 주입 — CloudFront Function/Lambda@Edge에서 flow 메타(API 조회)를 HTML에 삽입하거나, sitemap 생성 시점에 flow별 정적 HTML 셸을 프리렌더해 S3에 업로드. 삭제된 flow는 404/410 반환.
- **Priority**: 1

### T2. 홈페이지가 sitemap에 없음

- **Issue**: sitemap.xml에 `/flows/*` 10건만 있고 `https://flow.eureka.codes/` 루트가 없음.
- **Impact**: Medium — 홈페이지는 외부 링크로 색인되겠지만, sitemap은 "색인 원하는 canonical URL 전체 목록"이어야 함.
- **Evidence**: `curl https://flow.eureka.codes/sitemap.xml` (10 URL, 루트 없음).
- **Fix**: sitemap 생성부에 루트 URL(및 색인 원하는 고정 페이지) 추가.
- **Priority**: 2

### T3. robots.txt의 placeholder Disallow

- **Issue**: `Disallow: /do-not-crawl-here/` — 존재하지 않는 경로의 placeholder 규칙.
- **Impact**: Low — 해는 없으나 관리 안 된 인상. `/editor` 같은 로그인 필요 경로는 오히려 명시적으로 Disallow할 후보.
- **Evidence**: `curl https://flow.eureka.codes/robots.txt`.
- **Fix**: placeholder 제거, 색인 불필요 경로(`/editor` 등 앱 전용 라우트)를 정책 결정 후 명시.
- **Priority**: 4

### T4. HTTPS/캐싱/리다이렉트 — 정상

- HTTP→HTTPS 301, HTML `cache-control: no-cache/no-store`(SPA 배포에 적합), CloudFront + S3 서빙 확인. 조치 불필요.

## On-Page SEO Findings

### O1. Open Graph 태그 부재

- **Issue**: `twitter:*` 태그는 있으나 `og:title`, `og:description`, `og:image`, `og:url`, `og:type`이 없음.
- **Impact**: Medium — 카카오톡·Slack·Facebook·LinkedIn 등 OG 기반 크롤러에서 공유 미리보기 이미지/제목 미표시. (Twitter/X도 OG를 fallback으로 사용.)
- **Evidence**: `apps/web/index.html` head — Twitter Card 블록만 존재.
- **Fix**: Twitter Card와 동일 값으로 OG 5종 추가. 기존 `images/screenshot-light.jpg`(813KB) 재사용 가능하나 1200×630 전용 OG 이미지 + 200KB 이하 압축 권장.
- **Priority**: 2 (quick win)

### O2. canonical 태그 부재

- **Issue**: `<link rel="canonical">`이 없음.
- **Impact**: Medium — 쿼리스트링 붙은 URL(공유 트래킹 파라미터 등)이 별도 문서로 색인될 수 있음. T1의 중복 문제를 악화.
- **Evidence**: `apps/web/index.html` head.
- **Fix**: 루트에 self-canonical 추가. per-flow 메타 주입(T1) 구현 시 flow URL도 self-canonical.
- **Priority**: 2 (quick win)

### O3. 언어 신호 불일치 (en/ko)

- **Issue**: `html lang="en"` + 영어 meta이지만, sitemap의 image:title은 한국어("AI 워크플로우 자동화 / 유레카(Eureka) 플로우(Flow)")이고 앱은 en/ko i18n 지원. hreflang 없음.
- **Impact**: Low-Medium — 단일 URL이 두 언어를 서빙하므로 hreflang 대상은 아니지만, 타깃 시장이 한국이라면 정적 HTML의 title/description에 한국어 키워드가 전혀 없어 네이버·구글 한국어 쿼리 노출이 약함.
- **Evidence**: `index.html`(en) vs sitemap image:title(ko).
- **Fix**: 주 타깃 언어 결정 후 meta를 일치시키거나, 한국어 랜딩 콘텐츠 경로를 별도 URL로 분리해 hreflang 적용. `[TBD: 타깃 시장 우선순위 — product-marketing.md에도 미정]`
- **Priority**: 3

### O4. viewport `user-scalable=no`

- **Issue**: `maximum-scale=1, user-scalable=no` — 사용자 확대 차단.
- **Impact**: Low(SEO) / Medium(접근성) — Lighthouse 접근성 감점 요인. 캔버스 앱 특성상 의도된 설정일 수 있음.
- **Evidence**: `apps/web/index.html` viewport meta.
- **Fix**: 캔버스 제스처 충돌이 이유라면 유지하되 의도임을 기록, 아니면 제거.
- **Priority**: 5

### O5. 구조화 데이터 — 양호, 확장 여지

- **현황**: WebApplication JSON-LD가 정적 HTML에 있음(가격 $0, creator 포함) — SPA에서 흔히 빠지는 항목인데 잘 갖춰짐.
- **확장**: per-flow 페이지(T1 해결 시)에 flow별 `CreativeWork`/`HowTo` schema를 함께 주입하면 sitemap의 image 데이터와 시너지. `Organization` sameAs(GitHub 등) 추가 검토.
- **Priority**: 4

## Prioritized Action Plan

1. **[Critical] T1** — public flow URL per-page 메타/프리렌더 + 삭제 flow 404 처리. (색인 전략의 전제)
2. **[Quick win] O1+O2** — `index.html`에 OG 태그 5종 + canonical 추가. 1-file diff.
3. **[Quick win] T2** — sitemap에 홈페이지 추가.
4. **[결정 필요] O3** — 타깃 언어 전략 확정(ko 우선이면 meta 한국어화 검토).
5. **[Backlog] T3, O4, O5** — robots 정리, viewport 검토, schema 확장.
